# IzyKube capability evidence matrix

Audit date: 2026-07-23<br>
Repository baseline: `fc1ded78b8a7f0b54118229a128a871531268052` (2026-07-12)

This matrix describes evidence present in this repository at the baseline above. It is an engineering inventory, not a legal opinion or a claim of intellectual-property ownership.

## Status definitions

- **implemented**: working code exists and a reproducible automated verification is available.
- **partial**: relevant code exists, but an important path or complete reproducible verification is missing.
- **planned**: no product implementation was found; the item is roadmap only.
- **external dependency**: the capability is supplied by a third party. Repository scripts or configuration may install or connect it, but that does not make the third-party component IzyKube background IP.

Commands are run from the repository root. A passing test proves the behavior covered by that test; it does not establish production suitability or ownership.

## Interpretation limits

- “Implemented” is scoped to the cited behavior and test; it is not a statement of completeness, security certification, or production readiness.
- Git history establishes that content was present in a commit. It does not by itself prove authorship, freedom to operate, or legal ownership.
- Third-party licenses and model/data terms must be assessed separately.
- The relationship between the engineering cutoff and a particular European call, grant, or submission date **requires legal validation**.
