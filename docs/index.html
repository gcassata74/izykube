Core features

Everything needed to design and run Kubernetes architecture

IzyKube supports the full design-to-deploy loop while staying compatible with standard Kubernetes workflows.

Visual Namespace Modeler

Place workloads, services, config maps, ingresses, secrets, and volumes on a shared canvas.

Version Snapshots

Save alternative versions of the same namespace and roll back quickly during exploration.

YAML and Helm Export

Generate deployment-ready Kubernetes manifests or package the same model as a Helm chart.

Deploy and Undeploy

Apply generated resources directly to a connected cluster and remove them when needed.

Runtime Inspection

Overlay live cluster information to detect missing resources and drift from intended design.

Open Architecture

Built with Angular, Spring Boot, MongoDB, and Kubernetes-friendly infrastructure.

Quickstart

Run IzyKube locally in minutes

Spin up MongoDB, k3s, registry, and IzyKube using Docker Compose.

1) Clone the repository 
git clone https://github.com/izylife/izykube.git
cd izykube
2) Start the full stack 
docker compose up
3) Open the UI and model your first namespace 
http://localhost:8090

FAQ

Common questions before adoption

Is IzyKube a hosted SaaS?

No. IzyKube is open-source and self-hostable. You can run it locally or in your own infrastructure.

Does it replace kubectl or Helm?

No. It complements your existing tooling by generating manifests and charts from a visual architecture model.

Who is it for?

Platform teams, DevOps engineers, architects, and backend teams that need faster and clearer Kubernetes delivery.
